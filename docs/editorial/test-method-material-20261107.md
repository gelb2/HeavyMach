## 집필 방향

글의 화자는 복원을 지시하고 직접 플레이한 개발자다. 원작과 비교할 실행본을 마련하고, 진행도에 막히지 않는 치트 앱으로 조건을 설정한 뒤, 실제 클라이언트에서 확인한 과정을 쓴다. 구현·자동 실행·계측을 수행한 주체는 Codex로 적는다.

집필 때 확인할 결과는 검사별 입력, 기대값, 실제 결과, 실패와 수정 내역이다. 치트 기능으로 설정한 상태와 게임이 계산한 결과를 나누고, 전체 검사를 요구한 당시 지시와 실행 기록에서 확인되는 범위를 대조한다.

- [ ] 본문에 “프레임 검사는 p99 16.67ms, 25ms 초과는 0회였다.”라는 문장을 넣고 바로 뒤에서 측정 조건과 뜻을 설명한다.
- [ ] 60fps는 1초에 화면을 60번 갱신하는 속도이며, 한 번의 간격이 약 16.67ms라는 설명을 붙인다. p99는 프레임 간격을 짧은 순서로 정렬했을 때 약 99% 지점의 값이다. 평균만 보면 숨을 수 있는 긴 프레임을 살펴보려고 이 수치와 25ms 초과 횟수를 함께 기록했다.
- [ ] 위 수치는 2026-11-07 MachDefense의 실제 iPad Air 13인치(M2) 치트 앱 검사다. 설치 유닛 14종과 Lv.10 기지·유닛·포탑을 준비하고, 전체 게임 세션에서 전투300프레임과 전투 중 HUD 스크롤300프레임을 측정했다. CADisplayLink의 연속 시각 차이를 사용했고 디버거는 붙이지 않았다.
- [ ] 게임 계산과 렌더 제출에 걸린 CPU 시간도 함께 쓴다. p95는 전투5.24ms, 전투·스크롤5.94ms였다. 측정 구간의 저장 쓰기는0회였다. 이 결과를 HeavyMach의 측정값으로 옮기지 않고 MachDefense 사례로 연결한다.
- [ ] 별도 월드 검사1,800프레임에서는 포탑6대를 동시에 생성한 시점에 CPU40.85ms와 25ms 초과1회를 기록했다. 검사 장면별 결과를 나란히 쓴다.

집필할 과정:

1. 포팅판을 원작 동작의 비교 기준으로 삼고 데이터·그림·소리를 대조했다.
2. 공용 게임 코드와 플랫폼 연결을 나누어 재구현했다. 사용자는 직접 플레이하면서 기지 발사 때의 끊김과 음향 복귀 문제 등을 지적했다. 당시 원인·수정·재검사 근거를 연결한다.
3. 진행도와 자금에 막히지 않고 모든 강화·무기·미션 조건을 만들 수 있게 치트 앱을 만들었다. 검사는 실제 생산·발사·명중·강화·저장 함수를 호출했다.
4. 이번 확장에서는 공용 검사40개, Chrome·WebKit의 구매·복원·전투·입력 검사, 실제 iPad 기능 검사6개를 실행했다. 비활성 유닛에서 드래그가 취소되는 문제를 찾아 수정했다.
5. 기능 검사를 끝낸 뒤 실제 시간에 맞춰 전투를 돌렸다. HUD를 드래그하면서 프레임 간격, CPU 시간, 저장 쓰기, 텍스처 업로드를 함께 기록했다. 전투와 음향 성능 측정은 다른 기기의 부하 검사와 겹치지 않게 실행했다.
6. 최종 정식·치트 앱의 설치·실행·저장 보존 결과를 이어 적는다. 당시 완료한 범위는 해당 검사 기록에서 확인한다.
