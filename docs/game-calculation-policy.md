# 데미지와 게임 수치 계산 정책

정본: [canonical](canonical.md). 값의 출처는 원작1.13 데이터와 원본 함수다. 구현은 `GameData.cpp`, `Combat.cpp`, `Player.cpp`, `Enemy.cpp`, `GlobalInfo.cpp`, `Motion.cpp`, `World.cpp`. 보기 좋은 새 수식·난이도·상한을 임의 도입하지 않는다.

## 데이터와 연산

WeaponInfo의 dmg/spd/spdRand/aimRand/shotCnt/g/liveTm, MachDefinition의 hpMax/giveExp와 부품은 원본 MCH에서 읽는다. 적 HP/EXP를 플레이어 레벨에 맞춰 새로 스케일하지 않는다. float/double 승격, 연산 순서, 정수 나눗셈·절삭, ARM32 wrap은 동작의 일부다. float 상수를 double 리터럴로 치환하거나 FMA로 합치지 않는다. 코드의 `-ffp-contract=off`와 주소별 근거를 보존한다.

## 탄환 데미지 — tickBullet 0xa444

기본값 `D=WeaponInfo.dmg`, 무기 등급 `G=slot[0x2d]`다.

1. 플레이어가 적에게 발사한 탄환: `damage=D+(D/8)*G`. `/8`은 먼저 실행하는 정수 나눗셈이다.
2. Attack 활성일 때 위 결과를 float로 바꿔 `1.5f`를 곱한 후 int32로 절삭한다.
3. 적이 플레이어에게 발사한 탄환: 무기 강화/Attack 증폭을 적용하지 않는다. Defense 활성일 때 `D/2` 정수 나눗셈을 적용한다.
4. 충돌 처리 뒤 대상에게 해당 값을 전달한다. 관통 여부·파티클 풀·폭발음·이벤트 순서는 별도 원본 분기를 유지한다. 방어 처리를 Player.onDamage에서 다시 적용하지 않는다.

예: D=15,G=2이면 적에게17, Attack이면25다. `D*(1+G/8)`로 바꾸면 다른 값이 된다. 적탄15를 Defense로 받으면7이다. 이는 식 설명 예시이며 실제 무기의 dmg 표를 대체하지 않는다.

HP는 원본32비트 뺄셈 결과로 갱신한다. HP<1이면0과 사망 이벤트를 적용한다. 플레이어 피해>10의 흔들림은 `max(float(damage)/5,10)`, count4, delay0.3f다. 낙하 등 비탄환 피해에 탄환 방어 공식을 임의 재사용하지 않는다.

## HP·속도·강화

- 부품 등급: weapon0x2d, top0x2e, body0x2f, 정상 범위0..6. 화면 이미지 번호는 grade+1이다.
- 최대 HP: hp=256에서 `i=1 .. grade−1`마다 `hp=int(hp+50*pow(double(1.3f),i))`. 매 반복 정수 변환한다. 한 번의 최종 절삭으로 바꾸지 않는다.
- 이동 기본값: `((float(bodyGrade)*0.5f)*0.3f)+1.3f`. 실제 이동에는 틸트 입력·지형·dash가 추가된다. 이를 곧바로 초당 월드 이동거리로 부르지 않는다.
- Speed 패시브는 이동 speed에1.3f를 곱한다. top 강화는 최대 HP를 다시 계산하고 전량 회복한다. body 강화는 이동속도를 갱신한다.
- 강화 선택과 마감 애니메이션의 pause 해제 순서를 보존한다. 0x2c를 임의의 소비 포인트로 간주하여 차감하지 않는다.

## 경험치 — 0x105f8 / 0x106e0

내부 레벨은0..99이고 화면은 내부값+1이다. 임계치는 `base=1.5f,sum=0`에서 i=0..level을 반복해 `sum=armVFPInt(double(sum)+300*pow(double(base),double(i)))`로 누적한다. 매 반복 뒤 base>1.25f이면0.01f를 뺀다. armVFPInt는0방향 절삭과 int32 포화, NaN→0을 보존한다.

EXP는 int32 wrap 합산한다. 임계치를 넘고 level<99일 때 한 번의 호출당 최대 한 레벨만 올린다. 남는 EXP는 유지한다. EXP gauge는 원본 previous/next 차이로 계산하고 위쪽1만 제한한다. 이 함수 자체는 파일 저장을 호출하지 않는다.

EXP 아이템은 해당 레벨 필요 구간의1/4,1/2, 또는 `int(float(interval)/1.5f)`를 지급한다. 이름 `EXP_Qurter` 등 원본 오자를 정정해 자원 키를 바꾸지 않는다.

## 탄약·패시브·난수

중복 무기 탄약은 기존값과 획득량을32비트로 합하고, 이번 획득량×6을 상한으로 쓴다. 원본 burst 종료 시 소모·기본 무기 예외·선택/삭제 순서를 유지한다. charge preview와 실제 저장 값을 혼동하지 않는다.

패시브는 Defense/Attack/Booster/Speed이며 획득 때60초를 누적한다. GUI tick마다 원본 float `0x3c888889`만큼 줄이고 정수 표시는 절삭한다. 원본 GUI tick의 수명 근거는 [수명 근거](session-lifecycle.md)다. 2026-10-25 사용자 요청으로 연 정지 메뉴/비활성 상태에서는 호스트가 전투와 패시브 tick을 함께 멈춘다. 결과/업그레이드 선택 절차는 [실행 정책](runtime-policy.md)을 따른다. 임의 wall-clock 만료를 추가하지 않는다.

메뉴·타이틀·전투·아이템은 공통 xorshift32 RNG를 사용한다. `state=max(state,1); state^=state<<13; state^=state>>17; state^=state<<5; result=state&0x7fffffff`. 시드가 같아도 호출 횟수/순서가 다르면 결과가 달라진다. 전투마다 별도 RNG를 만들지 않는다. 탄환 속도는 독립 난수2회, 조준 오차는1회를 사용하며 원본 조준 오차 범위는[-aimRand,0]이다.

## 검증과 미확인

필살기 `P_Wpn_RaderBomb`, `P_Wpn_RaderMsl`, `P_Wpn_RaderLsr`는 원본 type5 연사를 사용한다. 속도0은 목표X±50에 생성하며, 속도가 있으면 탱크 위에서 목표점을 향해 원작 각도 분산을 적용한다. 연사 중 목표점을 소비하므로 터치 해제를 가짜 좌표로 전달하지 않는다. 2026-10-25 후방 낙하 수정은 호스트 입력 좌표 수정이며 `Combat.cpp`의 분산·중력·탄약·데미지 수식을 변경하지 않았다.

수식 변경은 경계·정수절삭·강화/패시브 조합과 실제 피해 경로를 검사한다. `CombatTests`, `PlayerTests`, `CoreTests`, `AmmoSyncTests`, `GameSessionTests`가 현재 소비 검사다. 원본 주소/데이터 필드/증거 없이 새 값을 채우지 않는다. 데이터 파싱이나 원본 대응의 미확인은 [소스 범위](source-coverage.md)에 남긴다. 이 문서가 전체 원본 함수 동등성 인증을 뜻하지 않는다.


## 확장 시야와 전투 활성

2026-10-25 승인된 캔버스 확장은 화면 가시성과 해당 영역의 전투를 함께 넓힌다. 보이는 적은 원래 탄환 충돌·데미지·보상 함수를 사용한다. 보스의 이동·무기AI는 아래 원작 접근 조건에서 시작한다. 더 많은 적이 일찍 보이므로 전투 시작과 난수 소비 순서가 원본480과 같다고 주장하지 않는다. 원본480 비교 모드에서는120프레임 난수·저장·draw 순서를 따로 검증한다. 에셋 크기와 이동·데미지·탄약·EXP 수식은 동일하다.


확장 모드의 맵 적은 보이는 부품이 뒤늦게 나타나지 않도록 미리 생성한다. 보스는 표시/피격 준비와 이동·무기AI·전선 잠금 시작을 분리한다. 이동·무기AI·잠금은 원본 배치 위치가 player+500 안에 들어오는 원본10단위 진행 샘플에서 켠다. 먼저 처치된 보스는 잠금을 켜지 않으며 다른 살아있는 보스의 잠금을 해제하지 않는다. 이동한 보스의 현재 위치로 접근 조건을 다시 정의하지 않는다. 원본480 시작은 기존 생성 조건을 유지한다. 기체를 두 번 조립하거나 검사 목적으로 별도 게임 난수를 소비하지 않는다.

보스가 접근을 기다린 시간은 무기 AI 대기 시간에 포함하지 않는다. 활성 때 기존 난수 지연의 시작 시각을 맞추며 새 난수를 뽑지 않는다. 비행 machType1은 헬기 전용이 아니다. 미션3-5의 Boss05는 항공기 E_Boss02를 사용한다. 원작의 player+120·목표 속도±0.5·frontLine−30을 화면 폭에 비례해 바꾸지 않는다. [회귀 수정 근거](boss-motion-fix-20261025.md).

## 사용자 승인 VTOL 추가

야크141은 Heli004의 HP210/EXP10, 해리어는 Heli008의 HP400/EXP25, F35B는 E0604의 HP900/EXP60을 참조한다. 무기는 각각 E_Wpn_ASM, E_Boss_Wpn_01, E_0604_Wpn 원본 정의를 공유한다. 데미지·탄수·탄속 수식을 복제하지 않는다. 2026-11-07 요청에 따른 고정 배치152개는 전체35개 스테이지에 시작 시 추가하며 배치 생성에는 난수를 쓰지 않는다. 새 기체의 생성·비행·무기 AI 난수는 기체별 상태를 사용해 기존 공유 난수를 소비하지 않는다. 추가 탄환의 충돌·파괴·아이템 등 실제 전투 결과는 기존 전투 경로를 따른다. ## 정식·치트 앱 자동조준 — 전용 개발 브랜치

`feat/auto-aim-ipad-validation`의 선택 기능이다. 정식·치트 앱에 같은 A 토글·표적 전환·사격 UI를 제공한다. `AutoAim.hpp`와 `GameSession.cpp`는 원본 tick 순서의 탄속·중력·수명으로 도달 tick과 포신 각도를 계산한다. 발사 직전 플레이어 위치·포구·적 이동을 다시 반영한다. 낮은 경로가 지형에 막히면 높은 경로도 검사한다.

2026-10-27 후속 지시로 C 명중 보정 기능을 삭제했다. 자동조준은 목표 선택·포신 각도·지원 공격의 목표 좌표만 정한다. `setBulletFire`가 생성한 탄속·각도 분산·시작 위치를 덮어쓰지 않으며 비행 중 표적을 따라 속도를 바꾸지 않는다. 공중 지원 3종의 원래 가로 분산도 유지한다. 피해·탄약·재장전·중력·관통은 기존 `Combat.cpp`와 데이터 규칙을 사용한다.

자동조준 탄환의 대상 ID는 화면 밖 충돌 판정과 검사 집계에만 사용한다. 탄환을 표적으로 이동시키지 않는다. 산탄 분산과 발사 후 적의 방향 전환 때문에 빗나갈 수 있다. [구현 계획](auto-aim-plan-20261026.md), [검사 결과](public/auto-aim-ipad-20261027.md).

## 쉴카·퉁구스카

기관포는 `E_Tank_Wpn_01`의 흰색 탄환·효과·소리를 복사하고 미션 번호에 맞는 Tank 무기의 피해·속도를 사용한다. 쉴카 6발, 퉁구스카 4발이며 발사 간격은 0.2초다. 퉁구스카 미사일은 `E_ArmoCar_Msl_01..05`의 값으로 2발을 0.5초 간격으로 쏜다. HP·EXP는 해당 미션에 등장하는 원작 Tank 정의의 체력순 중앙 항목이다. 추가 수는 미션별 Tank 수×1.3을 반올림하고 35개 스테이지에 배분한다. [정확한 수량·값](ground-aa-expansion.md).
