현재 main은 전차 이동·점프·사격, 무기·부품·강화, 미션·보스·결과 화면과 저장을 제공한다. 넓은 화면, Apple·Android 지원, 자동조준, 항공기 6종과 지상 적 2종, HUD 편집과 기기 간 복원 코드는 내가 추가로 기획하고 Codex에 구현을 맡긴 기능이다. 웹판은 [fastutlego의 PR #24](https://github.com/gelb2/HeavyMach/pull/24)로 추가됐고, 나는 그 구현을 바탕으로 PWA와 Tauri 배포를 요청했다.

## 넓은 화면과 메뉴

나는 기존 그림을 확대하는 대신 캔버스를 넓혀 더 많은 월드를 표시하도록 요구했다. Codex는 화면 비율에 따라 보이는 범위를 늘리고, 새로 열린 좌우 영역의 터치도 월드 좌표로 변환했다. 적이 일찍 보이는 것과 전투를 시작하는 조건은 별도로 다뤘다.

타이틀·모드·미션 메뉴는 중앙의 기존 에셋을 유지하고 같은 색조의 배경을 좌우에 붙였다. 나는 경계 단절과 검은줄을 발견해 수정을 요구했고, Codex가 그림 연결과 텍스처 UV를 고쳤다. 메뉴 전환은 화면 전체를 덮는 네 도어 조각으로 바꿨다. 결과 그림 뒤로 전장이 노출되던 문제도 수정했다.

[화면 확장·도어 검사](fullscreen-transitions-20261027.md) · [좌표 정책](../coordinate-policy.md)

## 플랫폼·입력·치트 앱

나는 iPhone·iPad·Mac을 하나의 workspace에서 관리하고, 게임 코드와 자원을 공유하도록 요구했다. iPad는 터치·틸트와 키보드를 함께 지원한다. Codex는 Mac을 AppKit 앱으로 구현했다. 키보드로 이동·점프·조준·발사·무기 전환·메뉴를 모두 다룬다. Shift는 기울기와 포신 각도를 세밀하게 조절한다.

치트 앱은 일반 앱과 다른 앱 ID·저장을 사용한다. 미션·전체 무기·부품·강화 등 시작 조건을 바꿀 수 있어 진행을 반복하지 않고 무기와 적을 검사할 수 있다. 키보드와 터치 입력은 실제 게임의 공용 처리 경로를 사용한다.

[조작](gameplay-guide.md) · [구조](architecture.md) · [치트 검증 방법](../validation-mode.md)

Android 일반·치트 앱도 같은 C++ 게임 규칙과 자원을 사용한다. 터치·틸트·키보드, 자동조준, 추가 적과 HUD 편집을 지원한다. 기존 Apple 파일을 유지하면서 Android의 화면·입력·음향·저장 연결을 따로 구현했다. [Android 개발 과정](android-development-20261030.md), [설치](build-and-install.md#android-빌드와-설치), [Galaxy 플레이](android-gameplay-20261030.md).

## 웹·PWA·Tauri Mac

[웹판](https://gelb2.github.io/HeavyMach/)은 브라우저에서 실행하거나 홈 화면에 PWA로 설치할 수 있다. 시작 화면에서 설치를 먼저 안내하고 브라우저 플레이도 제공한다. 자원 다운로드와 검사가 끝나면 오프라인으로 실행할 수 있다. 같은 C++ 게임 규칙을 WebAssembly로 빌드하며 터치·틸트·키보드·트랙패드를 지원한다.

Tauri Mac은 이 웹 게임을 앱에 포함하고 OS 파일 백업을 더한다. 웹 저장소가 비면 마지막 정상 파일에서 복구한다. 로컬 앱 빌드와 플레이·복원·종료를 확인했다. [Tauri Mac 다운로드](https://github.com/gelb2/HeavyMach/releases/tag/tauri-mac-20261102) ZIP을 제공한다. 공증과 Windows 버전은 남은 과제다. [웹/PWA 설치](../../Distribution/Web/README.md) · [Tauri 빌드·저장](../../Desktop/Tauri/README.md).

## 복원 코드

나는 서버나 계정 없이 게임 진행을 다른 플랫폼으로 옮기도록 요구했다. 슬롯 선택 화면의 TRANSFER PROGRESS에서 `HM1-` 코드를 생성하고 다른 기기에 입력한다. 미션·경험치·무기 순서·탄약·부품 강화, HUD 배치와 키·조준 설정을 옮긴다. 탱크 외형은 복원한 부품 강화 상태로 다시 구성된다.

Apple은 전체 슬롯을 복원한다. Android·웹/PWA·Tauri는 전체 또는 선택 슬롯을 복원하며 HUD·조작 설정 포함 여부를 고를 수 있다. 코드를 검사한 뒤 확인 화면에서 복원한다. 기존 데이터는 먼저 백업하고 적용 결과를 다시 읽어 비교한다. 코드 생성·입력은 슬롯 선택 화면에서 제공한다.

`Modules/SaveTransfer`가 공용 형식과 검증·복원을 담당한다. 게임 코어의 이동·탄도·적·피해 계산과 원래 슬롯 구조는 유지했다. [모듈](../../Modules/SaveTransfer/README.md) · [실제 기기와 공개 웹 검사](validation.md#게임-버튼과-복원--2026-11-02).

## HUD 편집과 게임 버튼

전투를 멈추고 SET GAME UI를 누르면 탱크·지형·적이 보이는 화면에서 버튼·계기판·장식을 끌어 옮길 수 있다. 버튼 판정도 그림과 함께 이동한다. 기본 복원·취소·적용을 제공한다. [화면·검사](hud-improvement-plan-20261028.md).

HUD 편집 도구와 복원·키 설정의 추가 버튼은 원작 버튼 그림·눌림·입력 절차로 그린다. 기존 메뉴와 SET GAME UI는 유지했다. OS와 브라우저는 코드 문자열 입력·클립보드·파일 선택을 담당한다.

## 지상 적 2종

쉴카는 흰 총탄 6발을 연사하고, 퉁구스카는 흰 총탄 4발과 미사일 2발을 연사한다. 기존 지상 유닛의 부품 조립과 움직임을 재사용하며 레이더는 포탑과 별도로 회전한다. 35개 스테이지에 152대를 추가했다. 쉴카 포탑 높이는 내가 요구한 게임 내 비율에 맞췄다. [최종 그림·배치·검사](ground-aa-art-20261028.md#두-포탑-높이-맞춤).

## 자동조준

### 기획 의도와 요구

나는 아머드 코어6, 에이스 컴뱃7·8의 표적 선택·추적을 참고해 자동조준을 요구했다. 탱크를 이동하고 점프하면서도 포신이 표적을 따라가고, 별도 버튼으로 표적을 바꿀 수 있어야 했다. 기존 터치 조준·발사도 ON/OFF 전환으로 남기도록 했다.

나는 처음에 무기의 포물선과 적의 움직임을 계산해 반드시 명중하는 조준을 요구했다. Codex는 탄속·분산·비행 경로까지 수정하는 C 보정을 넣었다. 나는 그 영향을 확인한 뒤 삭제하도록 지시했다. 최종 기능은 표적 선택과 포신 조정이다. 발사된 탄환은 원래 무기 규칙으로 이동한다.

### 표적과 포신 계산

`GameSession`은 살아 있는 적 중 탱크보다 월드 X가 큰 적을 고른다. 최초 선택은 거리 제곱이 가장 작은 적이며, 이후에는 화면 밖으로 나가도 선택을 유지한다. 죽거나 제거되거나 탱크 뒤로 이동한 적은 해제하고 다른 전방 적을 고른다. 표적 전환은 거리순 후보를 사용한다. 적이 없으면 기본 각도 0.1rad로 돌아간다.

적은 스테이지 안에서 증가하는 정수 ID로 식별한다. 스테이지 시작 때 적 목록과 선택 ID를 함께 초기화한다. 표적을 해제한 직후 같은 적을 즉시 다시 고르는 상황도 처리했다.

`AutoAim.hpp`는 무기의 속도·중력·수명과 적의 직전 이동량으로 최대 600tick 범위의 도달 후보를 찾는다. 실제 탄환처럼 중력을 먼저 적용하고 위치를 갱신한다. 포신 각도가 바뀌면 포구 위치도 달라지므로 포구와 탄도를 세 차례 다시 계산한다. 낮은 탄도가 지형에 막히면 높은 탄도를 검사하고, 공중 지원 무기는 상공의 발사점을 반영한다.

이 계산은 `spawnBullet`의 탄속·분산을 바꾸지 않는다. 표적의 발사 후 움직임과 탄환 분산에 따라 빗나갈 수 있다.

### 버튼과 표시

HUD의 A 버튼은 자동조준 ON/OFF, 화살표 버튼은 표적 전환, 조준경 버튼은 사격이다. 버튼의 금속 질감·회색·노란색과 눌림 상태는 기존 점프·메뉴·무기 버튼에 맞췄다. 내 지시에 따라 화살표·조준경 버튼 위치도 바꿨다.

표적에는 모서리와 사선 장식, `LOCKED`·`TRACK`·`BLOCKED` 상태를 표시한다. 화면 밖 표적은 가장자리 방향 표시로 연결한다. 모드 전환 때 발사 유지 입력을 정리하며, 자동조준을 끄면 터치 조준·발사로 돌아간다.

![자동조준 표적과 하단 조작 버튼](media/gameplay-20261027/01-auto-aim.png)

Codex가 C 삭제 뒤 실행한 코어 20개와 Apple 입력 검사는 통과했다. 자동조준 추가 전 커밋과 비교한 수동 사격 20무기 × 3시드 × 420프레임, 총 25,200프레임 기록은 바이트 단위로 같았다. 화면 밖·지형 아래·표적 없음 상태를 더 쉽게 알아보게 하는 UI는 후속 과제다.

## 수직이착륙기 3종

### 기획과 외형

나는 야크·해리어·F35 계열을 헬기처럼 움직이는 공중 적으로 요구했다. 기존 적을 대체하지 않고 배치 사이에 추가하며, 수량은 미션의 헬기 평균을 참고하도록 했다. Codex가 요청에 없던 외형 재해석을 넣은 첫 시안은 다시 그리도록 했다. Codex는 실물 형상을 보존하는 규칙을 아트 스킬에 추가하고, 사진·도면으로 기수·흡입구·날개·꼬리 비례를 확인했다. 기존 헬기는 색조·질감의 참조로 사용했다. 새 시안을 채택한 뒤에는 앞으로 현실의 유닛을 추가할 때 이 절차를 쓰도록 지시했다. [첫 시안과 수정 지시](vtol-art-and-loadout-20261027.md)

이후에는 외곽선 정리와 앞쪽 불꽃 삭제를 요구했다. Codex가 그림과 효과를 수정했다. 세 기체의 길이는 Heli001 몸체 99보다 길고 Heli006 몸체 126보다 짧게 정했으며 높이는 비례 축소했다. 그림은 로드 때만 축소하고 GPU에서 재사용한다.

| 기체 | HP / EXP | 재사용한 무장 | 표시 길이 |
|---|---|---|---:|
| Yak-141 | 210 / 10, Heli004 기준 | E_Wpn_ASM, 단발 미사일, 피해 25 | 112 |
| Harrier GR3 | 400 / 25, Heli008 기준 | E_Boss_Wpn_01, 2발 기관포, 피해 50 | 108 |
| F-35B | 900 / 60, E0604 기준 | E_0604_Wpn, 2발 미사일, 피해 100 | 116 |

세 기종과 무장 재사용은 내 요구다. 참조 유닛·무기 ID와 위 수치는 Codex가 제시한 구현안에 따른다.

### 이동과 배치

기존 헬기의 `machType=1` 이동을 재사용한다. 새 기체에만 수평 속도에 따른 최대 8도, 수직 속도에 따른 최대 3도의 기울기를 더한다. 자세는 목표각까지 서서히 변한다. 포구·후방 노즐·피격 범위도 회전을 따른다. 불꽃은 기존 배기 그림을 후방 노즐 하나에 붙인다.

`VTOL.cpp`는 데이터 로드 뒤 새 정의와 배치를 추가한다. 기존 적 1,182항목의 이름·좌표·순서·보스 플래그를 유지했다. 미션별 일반 헬기 수를 모든 서브미션 수로 나눠 반올림하고, 선택한 스테이지에 그 수만큼 배치했다.

| 기체 | 등장 미션과 수량 | 합계 |
|---|---|---:|
| Yak-141 | 2-2: 5, 2-4: 5, 3-2: 7, 4-2: 4, 5-2: 9 | 30 |
| Harrier GR3 | 3-3: 7, 4-3: 4, 5-3: 9, 6-3: 10, 7-2: 11 | 41 |
| F-35B | 6-2: 10, 6-4: 10, 7-3: 11, 7-4: 11 | 42 |

14개 서브미션에 총 113대다. 미션1·8과 Survival 배치는 유지했다. 맵 양끝 300, 보스 주변 600을 피하고 지형보다 140 높은 지점에 분산한다. 새 유닛은 별도 난수 상태를 사용해 기존 적의 난수 호출 순서를 바꾸지 않는다.

Codex의 자동 검사는 원래 배치 보존, 중복 추가 방지, 이동·발사·자세·정지·격파와 20무기 × 3기종의 충돌을 다뤘다. 모든 미션의 추가 난이도와 장시간 발열은 아직 검사하지 않았다.

## 럭스루나에 도색 전투기 3종

[왜 럭스루나에인가](lux-lunae-intent-20261028.md)에서 기종과 도색을 고른 이유, 보스전의 긴장감을 높이려던 의도와 직접 플레이한 결과를 설명했다.

### 기획과 무장

나는 F-22·Su-57·MiG-31을 럭스루나에 편대 도색으로 추가하고 금색 조종석 유리를 요구했다. 내구력은 가장 강한 일반 헬기의 1.7배, 무장은 기존 미사일 재사용으로 정했다. 단발 미사일은 3연사, 2발 미사일은 3묶음으로 발사하도록 구체화했다.

| F-22 | 765 | E_Wpn_ASM 파생, 피해 25 | 1발씩 3연사 | 112 |
| Su-57 | 765 | E_Wpn_ASM 파생, 피해 25 | 1발씩 3연사 | 116 |
| MiG-31 | 765 | E_0604_Wpn 파생, 피해 100 | 2발씩 3회, 총 6발 | 120 |

HP는 일반 Heli 정의의 최대 450 × 1.7이다. 미사일 속도는 160에서 200으로 25% 높였다. 연사 속도는 최초 25% 증가에서 내 요청으로 **10% 증가**로 줄였다. 시간 간격을 1.1로 나눠 0.5초는 약 0.455초, 묶음 간 1초는 약 0.909초, 재장전 5초는 약 4.545초가 된다. AI 대기에도 같은 비율을 적용한다. 원래 무기 정의의 피해·중력·분산·수명은 유지한다.

일반 앱을 플레이하다 기체가 공중에 갑자기 나타나는 모습을 발견했다. Codex에 수정을 요구했다. Codex는 생성 위치를 화면 오른쪽 밖으로 옮겨 기체 전체가 가려진 상태에서 들어오도록 수정했다. 진입 중에는 발사하지 않으며 게임을 멈추면 진입도 멈춘다. 기존 헬기·VTOL의 생성 규칙은 그대로다.
