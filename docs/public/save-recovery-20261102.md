# 서버 없이 진행도를 옮기는 복원 코드

<!-- language-nav:start -->
[한국어](save-recovery-20261102.md) | [English](../en/public/save-recovery-20261102.md)
<!-- language-nav:end -->

나는 아이폰에서 쌓은 경험치와 무기를 다른 기기에서도 그대로 쓰고 싶었다. 플랫폼마다 다시 시작하거나 계정을 만들고 서버에 저장하는 방식은 원하지 않았다. HeavyMach는 싱글플레이 게임이고, 복원할 것은 게임 안에 이미 있는 무기·부품·미션의 상태다. 그렇다면 그 상태를 코드로 내보내 다른 기기에서 다시 조립하면 된다고 생각했다.

그 발상에서 시작한 기능이 세이브 슬롯 화면의 **TRANSFER PROGRESS**다. iOS·iPadOS·Android·네이티브 Mac·웹/PWA·Tauri Mac이 같은 C++ 복원 모듈을 사용한다. 서버나 계정 없이 코드를 복사해 진행도를 옮긴다.

## 원작의 세이브 슬롯을 기준으로

처음부터 새로운 저장 모델을 설계할 필요는 없었다. 원작에는 3개 슬롯과 저장 구조가 있었다. 나는 그 구조를 훼손하거나 재해석하지 말고 참고해서 모듈을 만들도록 지시했다. 게임 도중에 코드를 만들면 아직 저장하지 않은 전투 상태까지 처리해야 하므로, 진입 위치도 세이브 슬롯 선택 화면으로 정했다.

코드에는 원작 저장 파일 3,624바이트와 복원판에서 추가한 설정을 담았다. 슬롯의 경험치, 미션 진행, 무기 순서·탄약, 탱크 부품과 강화 상태가 함께 이동한다. 탱크 외형은 복원된 부품 값을 게임이 읽어 다시 표시한다. 그림·소리·게임 코드를 복원 문자열에 넣을 필요는 없다.

| 포함하는 상태 | 복원 방법 |
|---|---|
| 원작 슬롯 3개 | 기존 저장 레코드와 필드 배치를 유지 |
| HUD 위치 | 10개 배치 값을 저장하고 새 화면 크기에 적용 |
| 키보드 조작 | 16개 키 바인딩을 복원 |
| 자동조준 설정 | 저장한 설정을 복원 |

전투 중인 적·탄환·탱크의 순간 위치는 담지 않는다. 슬롯의 마지막 저장부터 다시 시작한다. HUD·키·자동조준 설정은 슬롯별이 아닌 앱 전체 설정이다.

## 해시가 아닌 복원할 데이터

내가 처음 말한 표현은 ‘복원용 해시코드’였다. 구현한 문자열에는 실제 저장 데이터가 들어 있다. 해시만으로는 원래 진행도를 되살릴 수 없기 때문이다.

모듈은 저장과 설정을 직렬화하고, 반복 바이트를 줄이는 PackBits형 압축을 적용한 뒤 Base64url 문자열로 바꾼다. 접두어는 `HM1-`이다. 버전과 길이를 기록하고 CRC32로 잘린 코드나 잘못 붙여넣은 데이터를 검사한다. 암호화나 salt는 넣지 않았다. 이 게임의 진행을 직접 옮기고 복원하는 데 필요한 기능으로 범위를 정했다.

코드 생성은 저장을 읽는 작업이다. 총탄이 나가거나 키를 누를 때마다 코드를 만들거나 파일에 기록하지 않는다. 코드를 나중에 입력하면 **코드를 만든 시점**의 저장이 돌아온다. 이후 플레이한 내용까지 자동으로 합쳐지지는 않는다.

## 공용 모듈과 플랫폼 연결

나는 탄도와 이동을 공용화한 것처럼 복원 절차도 공용 모듈로 만들도록 지시했다. Codex는 인코딩·디코딩, 슬롯 선택, 값 검사, 복원 중단 처리를 `Modules/SaveTransfer`에 구현했다. 원작 전투 코어의 탄도·이동·피해 계산과 저장 레코드는 바꾸지 않았다.

플랫폼별 연결부는 각 앱의 저장을 읽고, 복원한 데이터를 실제 저장소에 쓴다. Apple은 앱 파일과 설정, Android는 앱 파일과 설정, 웹/PWA는 브라우저 저장소를 연결한다. Tauri는 웹뷰 저장과 별도의 OS 파일 백업을 연결한다. C++와 WebAssembly가 같은 입력에서 같은 코드를 만드는지도 검사했다.

| 플랫폼 | 화면에서 고를 수 있는 복원 범위 |
|---|---|
| iPhone·iPad·네이티브 Mac | 슬롯 3개와 설정 전체 |
| Android | 전체 또는 출발·도착 슬롯 선택, HUD·조작 설정 선택 |
| 웹·PWA·Tauri Mac | 전체 또는 출발·도착 슬롯 선택, HUD·조작 설정 선택 |

복원 버튼을 누르면 모듈은 기존 저장을 복원 전 코드로 보관하고, 적용할 목표 상태를 기록한다. 데이터를 쓴 뒤 다시 읽어 비교하고, 일치하면 복원 중 표시를 지운다. 도중에 앱이 꺼지면 다음 실행에서 남은 목표 상태를 다시 적용하고 확인한다. 여러 파일 중 일부만 바뀐 상태를 완료로 처리하지 않기 위한 절차다.

## 브라우저 저장과 Tauri 백업

웹/PWA는 IndexedDB에 진행을 저장하고, 설정에는 localStorage도 사용한다. 게임 파일의 오프라인 캐시와 진행 저장은 별개다. Tauri Mac은 웹뷰 밖의 앱 데이터 폴더에도 백업을 둔다. 앱을 다시 열 때 웹뷰 저장이 전부 비었으면 OS 파일에서 자동 복구한다. 일부 파일이나 설정만 누락됐으면 게임 시작을 막고 백업 복구를 선택하게 한다.

브라우저에서 사이트 데이터를 직접 지우면 진행도 지워질 수 있다. PWA 설치와 영구 저장 요청, 복원 코드를 함께 제공한 이유다. 복원 코드를 앱 밖에 남겨 두면 사이트 데이터가 없어지거나 앱을 다시 설치해도 그 코드의 상태를 가져올 수 있다.

7·14·30·40일 뒤로 페이지 시각을 바꿨다가 되돌리는 검사에서는 저장이 유지됐다. 브라우저 내부의 정리 시계가 같은 만큼 흘렀다는 검사는 아니므로, 실제 장기 미접속 관측은 남아 있다. [날짜 변경 결과](../evidence/web-date-retention-20261101.json)

## 버튼을 다시 만든 이유

처음 복원 진입 버튼은 iOS의 UIKit, Android의 네이티브 버튼, 웹·Tauri의 HTML/CSS로 따로 만들었다. 게임이 이미 실행되고 있었고 원작의 버튼 구현도 있었는데, Codex가 플랫폼 UI를 추가한 것이다. Galaxy PWA에서는 게임 문서만 전체 화면이 되면서 바깥에 붙인 복원 버튼이 보이지 않았다.

나는 멈춤 메뉴의 **SET GAME UI**처럼 게임 안에서 필요한 버튼은 원작자가 쓰던 방식으로 만들도록 지시했다. **SET GAME UI**는 원작 메뉴 에셋의 배경과 글자를 조합하고, 게임 렌더러와 기존 눌림·터치 판정을 사용한다. 복원 진입 버튼, 복원창의 작업 버튼, HUD 편집 도구와 키 설정 버튼에도 같은 절차를 적용했다.

기존 메뉴 그림과 버튼은 보존했다. 새 영어 글자는 정적 시트로 만들었고, 처음 나온 판타지 게임 같은 글꼴도 원작의 금색 글자와 테두리를 기준으로 다시 만들었다. 텍스트 입력과 클립보드처럼 플랫폼 기능이 필요한 부분만 앱과 브라우저에 맡겼다.

버튼 교체 후에는 COPY의 늦은 완료 문구가 복원 확인 요약을 덮던 문제, 모달 빈 영역을 누른 손가락이 남아 있을 때 다른 손가락으로 창을 닫으면 입력이 뒤 게임으로 넘어가는 문제, HUD 편집을 끝낼 때 남은 손가락 입력, Mac 복사·붙여넣기 메뉴도 고쳤다. [전체 경위와 수정 결과](../reviews/game-button-incident-20261101.md) · [트러블슈팅](troubleshooting.md)

## 실제로 확인한 범위

2026년 11월 1~2일 검사에서 iPhone의 진행을 기준으로 iPad·Android·네이티브 Mac·Tauri·PWA의 복원을 확인했다. 후속 버튼 수정본에서도 생성·입력·확인·복원·재시작을 검사했다. 아래 표는 플랫폼별로 확보한 근거를 구분한 것이다.

| 환경 | 확인한 결과 |
|---|---|
| iPhone·iPad·네이티브 Mac | 복원 UI, 저장 보존, 버튼 경계 입력 검사 |
| Galaxy 네이티브 | 일반·치트 앱의 후속 검사 각 7개, 기존 저장 유지 |
| 공개 웹·설치형 Chrome PWA | 웹 20개·PWA 18개 검사, 복원 데이터 대조, 오프라인 재시작 |
| Galaxy Chrome·설치 PWA | 각 9개 검사, 코드 복원·HUD·키·자동조준 설정 대조 |
| iPad Safari | 코드 생성·잘못된 코드·확인 취소·복원·재시작, 슬롯 레벨·외형·날짜 확인 |
| Tauri Mac | 실제 복원 후 종료·재시작, 저장 3,624바이트·HUD 173바이트·설정 일치 |

iPad 홈 화면 PWA에서는 업데이트된 시작 페이지와 복원 패널을 확인했다. 그 설치 PWA에서 복원 전체 절차를 다시 수행한 기록은 Safari 검사와 별개로 남아 있지 않다. 네이티브 Mac의 최신 프레임 검사는 p95 약 25~51ms로 기준을 통과하지 못했다. 이전 버전과 같은 조건의 비교 검사가 남아 있다.

## 현재 배포와 남은 일

웹/PWA는 [GitHub Pages](https://gelb2.github.io/HeavyMach/)에서 실행한다. Tauri Mac은 로컬 앱 실행과 복원을 확인했으며, 공개 설치본과 공증은 남아 있다. Windows 빌드도 후속 과제다.

최신 릴리스 태그는 v0.17이다. 현재 main에는 이후의 웹/PWA·Tauri·복원 코드와 버튼 수정이 들어 있다. 다음 릴리스에서는 앱에 표시되는 버전도 맞춰야 한다. 현재 iPhone은 1.13, Android는 0.16-android-dev를 표시한다. 480 논리 너비 복원 안내의 단어 줄바꿈과 네이티브 Mac 프레임 비교도 남아 있다. [구현 상태](implementation-status.md) · [남은 과제](roadmap.md)
