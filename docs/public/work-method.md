나는 게임업계에서 개발자로 일한 경험이 없다. HeavyMach를 복원하면서 Codex에게 맡긴 것은 구현이었다. 어떤 게임을 되살릴지, 원작에서 무엇을 지킬지, 무엇을 더할지는 내가 정했다. 직접 플레이하며 달라진 움직임과 소리, 그림을 지적하는 것도 내 일이었다.

## 계획과 보고서를 먼저 요구했다

나는 개발 계획을 먼저 세우고 보고서를 쓰게 했다. 빠진 요구가 있는지, 이해할 수 없는 구현을 제안했는지 읽었다. 과제가 너무 커 보이면 어느 파일을 고칠 것인지, 게임 규칙을 담은 공용 코드를 건드리는지 다시 물었다.

이런 질문이 필요했던 이유는 실제로 납득하기 어려운 구현이 나왔기 때문이다. 원작과 정상 동작하는 포팅판이 있었는데도 Codex는 다른 경로를 만들었다. 나는 내 표현대로, Codex의 기상천외한 개발 방향과 아키텍처 파괴행각, 하나에 꽂히면 업무지시까지 무시하고 자기 할 것만 하며 토큰을 태우는 행각을 막으려고 코덱스를 쥐어팼다.

## 총알이 나갈 때마다 저장하고 있었다

아이폰으로 돌려보니 포팅판에서 없던 끊김이 있었다. 조사 과정에서 나는 “발사 때마다 파일을 저장?”이라고 물었다. 초기 코드는 탄약·피격·경험치가 바뀔 때의 메모리 변경 통지를 파일 저장에 연결했다. 전투가 계속되는 동안 작은 상태 변화가 매번 디스크 쓰기가 됐다.

나는 전투 도중 값을 바꾸는 것과 저장 파일을 기록하는 것을 왜 묶었는지 따져 물었다. Codex는 슬롯 선택·다음 스테이지·게임 오버·메뉴 복귀로 저장 시점을 나눴다. 수정 뒤 180프레임 사격 중 저장은 0회, 메뉴 복귀 때는 1회였다. 기존 3,624바이트 저장 형식도 유지했다. [문제와 수정 기록](troubleshooting.md)

그림에서도 같은 일이 있었다. Codex는 UIKit을 거치는 경로에서 CPU 픽셀 처리와 이미지 생성·합성을 반복했다. 나는 게임 그래픽을 왜 그렇게 그리는지 물었고, 원작과 포팅판의 경로를 대조하게 했다. OpenGL ES 렌더링과 텍스처 재사용으로 고친 뒤에도 사격 효과음의 지연이 남아 음향 호출까지 따로 측정했다.

## 새 플랫폼 때문에 기존 앱을 망가뜨리지 않게 했다

Android 개발을 맡길 때는 이미 돌아가는 iPhone·iPad·Mac의 파일을 바꾸지 말라고 했다. Android 폴더에 새 실행기를 만들고, 기존 C++ 게임 코드와 자원을 빌드해서 쓰도록 했다. 화면·입력·오디오·생명주기를 연결하는 작업 때문에 기존 플랫폼의 전투 규칙까지 흔들어서는 안 된다고 봤다.

당시 작업 전후 Apple 소스·프로젝트·코어·자원 2,166개 파일의 해시가 같았다. Android에서 발견한 업그레이드 창 문제는 Android 쪽의 정지·입력 연결을 고쳤다. “공용으로 쓴다”는 설명만 듣지 않고 실제로 무엇을 바꿨는지 확인한 것이다. [Android 구현과 검사](android-development-20261030.md)

웹판은 [fastutlego의 PR #24](https://github.com/gelb2/HeavyMach/pull/24)에서 출발했다. 나는 기여자의 커밋을 보존하고, 이미 동작한 웹 구현과 후속 수정 3건을 바꾸지 않은 채 Tauri 실행기와 웹 배포를 추가하도록 지시했다. [첫 PR과 Tauri](first-pr-and-tauri-20261031.md)

## 게임 버튼도 다시 만들게 했다

게임이 이미 켜진 뒤 쓰는 버튼을 Codex가 Apple·Android·웹의 UI로 따로 만들었다. 원작의 버튼 에셋과 입력 절차가 있는데도 플랫폼마다 관리할 구현을 늘린 것이다. 나는 게임 안의 버튼은 원작 방식으로 만들고, 코드 입력처럼 운영체제가 필요한 기능만 플랫폼에 연결하라고 다시 지시했다.

추가 버튼을 게임 렌더러와 입력으로 옮긴 뒤에는 원작 버튼과 자원 1,453개가 보존됐는지 비교했다. 각 플랫폼에서 버튼을 누르고, 복원 코드를 생성·입력하고, 재실행 뒤 저장을 확인했다. [복원 코드와 버튼 수정](save-recovery-20261102.md)

기능마다 작업 브랜치를 나누고 커밋을 남기게 했다. 수정이 잘못되면 어느 변경부터 돌아가야 하는지 알 수 있어야 했다. main에 합칠 때는 내가 GitHub에서 직접 고친 원고도 대조하도록 했다. 보고서의 완료 표시만으로 일을 끝내지 않고, 내가 누를 버튼과 실제 실행 결과를 계속 확인했다.
