# 복원 요구와 완료 기준

## 목표

HeavyMach 1.13 IPA의 REA 분석으로 게임 코드를 복원하고, 그 소스를 현재 Xcode에서 ARM64 iPhone·시뮬레이터용으로 빌드한다. 원본 바이너리 실행만으로 소스 복원 목표를 충족했다고 판정하지 않는다. 원본 개발 소스와 복원 소스를 구분한다.

## 보존할 동작

- 원작480×320 비교 모드, 이미지·타일·메뉴 순서, 기체·적 외형, 효과음과 애니메이션을 보존한다. 2026-10-25 최신 사용자 승인으로 게임플레이 시야를 가로 확장하며 중앙HUD는 안전영역에 맞춘다. 후속 승인으로 타이틀·메뉴 원본 요소 재배치와 별도 생성 배경 확장도 허용한다. 원본 파일과 원본480 비교 모드는 유지한다. 실제 변환과 추가 가시성의 게임 동작을 검사한다.
- 기울기 이동, 터치 조준·사격, 부스터 점프, 피격·충돌·낙사·실패·일시정지·복귀를 보존한다. 시뮬레이터 입력 대체는 같은 게임 입력값을 만들며 게임 수치를 바꾸지 않는다.
- 원작 맵·부품·무기·적 배치와 진행·보스·경험치·레벨업·아이템·저장 규칙을 보존한다. Assault 전용 Life·결제·광고·후반 배치를 원작 요구로 추가하지 않는다.
- 기존 IPA·추출 원본·실패 증거·사용자 저장·Unity 작업을 보존한다. 수정이 필요한 현대 플랫폼 연결과 게임 규칙을 구분한다.

## 구현 증거

각 핵심 경로는 원작 함수 주소 또는 데이터 offset과 연결한다. 디컴파일의 타입·부동소수 비교·구조체 반환·분기 해석이 불명확하면 어셈블리와 호출부로 좁힌다. 재현 근거가 없는 편의상 구현은 추정으로 표시하고 확인 과제로 남긴다.

2026-10-24 최신 사용자 지시에 따라 별도 검증 앱에서 레벨업 직전 EXP, 무기·부품 단계, 미션·보스 직전 위치 등의 시작 조건을 지정한다. 실제 경험치 획득·업그레이드·충돌·전투·저장 함수와 화면으로 결과를 검증한다. 설정으로 만든 시작 상태와 실제 코드가 만든 결과를 따로 기록한다. 일반 앱·사용자 저장·원본 데이터는 변경하지 않으며 성공 판정을 강제하거나 실패 기준을 완화하지 않는다. 미완성 기능을 고정 반환값으로 가리고 완료로 보고하지 않는다. 자원을 변환할 때 원본 SHA와 파생본을 구분하고 시각·음향 결과를 비교한다.

후속 사용자 지시로 무적·무한탄약·낙하복귀를 사용하는 검증도 허용했다. 이 조건을 로그에 표시하고 실제 전투·출구·진행·저장 코드를 검사한다. 적 삭제·강제 클리어와 구분하며, 치트 검증 통과를 정상난이도 공략 성공으로 보고하지 않는다.

## 완료 판정

| 항목 | 필요한 증거 |
| --- | --- |
| 소스 기반 빌드 | 핵심 게임 코드가 포함된 재현 가능한 Xcode 소스 빌드. 게임 실행에 원본 ARM 명령 해석을 요구하지 않는 경로 |
| 시뮬레이터 | 설치·콜드 실행·타이틀부터 스테이지·입력·렌더 검증 |
| 실기기 | 기기·OS·빌드 식별, 서명·설치·실행 및 실제 조작 |
| 플레이 | 원본과 같은 이동·사격·충돌·점프·피격·낙사·아이템·무기·다음 스테이지 |
| 성장 | EXP 획득·레벨업·업그레이드의 정상 경로 |
| 저장 | 정상 저장 후 종료·재실행·동일 슬롯 진행 유지, 기존 사용자 저장 보존 |

## 사용자 승인 확장 — 공중 적3종

2026-10-27 사용자가 야크141·해리어 GR3·F35B 두 번째 시안을 채택하고 일반·치트 앱 적용을 지시했다. 기존 적1,182개 항목과 원본 MAP/MCH를 유지한다. 최초113개 추가 배치에서2026-11-07 요청에 따라 전체35개 스테이지·152개 배치로 변경한다. 새 기체는 원작 복원 범위와 구분한 승인 확장이다. [구현](vtol-expansion.md).
