## 발견 사항

### A01. 정본과 설계가 완료된 PWA를 남은 작업으로 설명한다

[정본](../canonical.md)의 Tauri 절과 [설계](../design.md)의 같은 절은 첫 Tauri 구현·20개 검사 결과 뒤에 PWA와 Mac 비교를 남은 일로 적고 있다. 실제로는 공개 Pages 배포와 Mac 비교, main 통합까지 진행됐다. 바로 아래 복원 코드 절도 main 통합을 미래 작업으로 적고 있다.

현재 구조는 최신 상태로 고치고, 첫 구현 당시의 수치는 날짜별 기록으로 연결해야 한다. 원작 복원 요구인 [restoration-contract](../restoration-contract.md)는 초기 iPhone 범위와 VTOL 확장만으로 현재 승인 기능 전체를 설명하지 못한다. 원작 보존 조건 뒤에 현재 플랫폼·추가 기능 요구로 가는 참조가 필요하다.

### A02. 작업 지침의 파일 동결 조건에 후속 승인 범위가 빠져 있다

[AGENTS.md](../../AGENTS.md)의 10월 31일 지시는 Apple·Android·웹 호스트 파일 전체를 동결한다. 이후 복원 코드 지시로 플랫폼 연결부와 빌드 구성이 바뀌었고, [허용 범위](../../Desktop/Tauri/save-transfer-scope.json)에 기록돼 있다. 정본에는 후속 승인 설명이 있지만 AGENTS의 해당 문단에는 없다.

다음 작업자가 읽는 입구에서도 초기 Tauri 동결 범위와 이후 승인된 복원 연결 범위를 함께 안내해야 한다. 기존 기여자 커밋 보존과 후속 파일 변경은 따로 기록한다.

### A03. PWA와 복원 코드가 업무별 문서 연결표에서 빠진다

[document-map.json](../document-map.json)에는 SaveTransfer·PWA 전용 업무가 없다. `Modules/*`가 복원 모듈까지 Apple 업무로 분류하고, `Distribution/Web/pwa/host.js`, `saves.js`, `sw.js`, Android `Transfer.inc`는 어떤 소스 경로에도 걸리지 않는다. 나머지 미연결 3개는 원본 인터페이스 선언이며 신규 실행 기능 누락과 구별했다.

복원 코드와 웹 배포 업무에 정책·모듈·플랫폼 어댑터·회귀 검사·실행 증거를 묶어야 한다. 새 소스가 어떤 업무에도 연결되지 않을 때 검사에서 알려줄 필요가 있다.

### A04. 공개 구조 문서에 현재 실행 플랫폼과 공통 모듈이 없다

[구조](../public/architecture.md)와 [Apple 플랫폼](../apple-platforms.md)의 모듈 표에는 SaveTransfer가 없다. 공개 구조 표에는 `Sources/Web`, `Web`, `Desktop/Tauri`, `Distribution/Web`도 없다. 실제 Apple 프로젝트에는 SaveTransfer 정적 프레임워크가 연결돼 있으며 Android는 C++, 웹 계열은 Wasm으로 같은 구현을 소비한다.

한 프레임 설명도 플랫폼을 구별해야 한다. 웹의 프레임 누적 처리와 WebGL2를 네이티브의 표시 호출당 1회 갱신·OpenGL 설명만으로 안내할 수 없다. [웹 이식](../web-port-20261028.md)과 실행 정책에는 별도 설명이 있으므로 이를 공개 구조 문서에 연결한다.

### A05. 구현 상태·설치·조작·목차가 최신 README를 따라가지 못한다

[구현 상태](../public/implementation-status.md)는 v0.17 기준이라고 명시하지만, [문서 목차](../README.md)는 이를 현재 기능의 안내로 연결한다. [공개 목차](../public/index.md), [설치](../public/build-and-install.md), [조작](../public/gameplay-guide.md)에서도 새 플랫폼과 복원 절차를 한 흐름으로 찾기 어렵다.

현재 main과 태그별 기능을 분리하고, 브라우저/PWA → Tauri → 네이티브 빌드 경로를 연결한다. 복원 코드 생성 위치, 전체/한 슬롯 선택, 덮어쓰는 값, 실패 시 복구를 조작 문서에 추가한다.

### A06. 저장 정책에 새 복원·백업 쓰기 경로가 없다

[실행 정책](../runtime-policy.md)은 원작의 정상 저장 지점과 플랫폼 저장을 설명한다. 새 모듈의 `before.hmcode`, `restore.hmcode`, 복원 전 보관·대기 기록·적용·재독출·완료, Tauri의 OS 백업은 같은 정책 안에서 연결되지 않는다.

게임이 정상 저장하는 시점, 플레이어가 복원 코드를 적용하는 시점, 호스트가 이미 저장된 값을 백업하는 시점을 구분해야 한다. [공통 모듈](../../Modules/SaveTransfer/README.md)과 [Tauri 저장 설명](../../Desktop/Tauri/README.md)에 있는 구현 내용을 상위 정책에 연결한다.

### A07. 같은 복원 모듈을 써도 슬롯 선택 UI는 다르다

Apple의 `HMTransfer.inc`는 세 슬롯 전체를 적용한다. Android `Transfer.inc`와 웹 UI는 전체 또는 한 슬롯을 선택한다. 이 차이는 모듈 README에만 있고 공개 조작 문서에는 없다.

모듈 통합 완료와 플랫폼별 UI 일치는 구분해야 한다. 현재 차이를 안내하고, Apple에도 한 슬롯 선택을 제공할지는 기능 요구로 정리한다. 모든 플랫폼의 입력창을 같은 절차로 직접 조작한 검사는 아직 남아 있다.

### A08. 웹·Tauri가 전투 중 SET GAME UI를 표시한다

정책은 일시정지 메뉴 진입이다. 실제 `Sources/Web/WebHUDEditor.inc`의 `updateHUDEntry()`는 `_hudLayoutFallback && !_gameMenu` 조건에서 편집 버튼을 노출한다. 저장된 HUD가 새 화면 비율에서 유효하지 않을 때 전투 중 버튼이 나타나는 경로다. main 병합 후 Tauri 실행 기록에도 같은 현상이 있다.

기본 HUD로 돌아가는 처리와 편집 진입을 분리해야 한다. 전투 중에는 버튼을 숨기고, 정지 메뉴에서 편집하도록 고친 뒤 복원된 배치·화면 회전·창 크기 변경을 검사한다. 이 감사에서는 코드를 바꾸지 않았다.

### A09. 게임 UI와 플랫폼 UI의 경계가 문서마다 다르다

[렌더 정책](../rendering-policy.md)은 HUD 편집 도구의 UIKit/AppKit·CoreText 합성과 웹 DOM 사용을 명시한다. 따라서 이 구현 전체가 기록 없이 들어갔다고 볼 수는 없다. 다만 상위 설계의 간단한 플랫폼 역할 설명과 새 복원 진입 버튼까지 일관되게 연결되지는 않는다.

멈춤 메뉴 스프라이트 버튼, HUD 도구 버튼, 복원 진입 버튼, 텍스트 입력·클립보드 창을 각각 목록화해야 한다. 현재 Android 버튼은 Kotlin에서 생성한다. [UI 전수조사](../ui-implementation-audit.md)에서 기존 게임 버튼으로 옮길 대상을 정한다.

[키보드 정책](../keyboard-input-policy.md)은 수동 조준 표시를 공통 동작으로 설명한다. 현재 Apple·Android에는 표시가 남아 있고, 웹·Tauri에서는 요청에 따라 숨겼다. 조준 좌표와 방향키 입력은 유지한다. 플랫폼별 표시 차이를 정책과 조작 안내에 반영해야 한다.

### A10. 번역 검사는 양쪽 문서에 함께 빠진 내용을 찾지 못한다

21개 국영문 쌍의 해시·제목·표·링크 대응은 통과했다. 그러나 두 언어의 구조·상태·설치 문서에 같은 새 기능이 빠져 있다. 번역 검사 통과는 현재 기능 설명의 완성을 뜻하지 않는다.

국문 기능표를 코드와 대조한 뒤 영어판을 함께 고친다. README·공개 문서·SaaS 자료에 대해 기능별로 연결 여부를 확인한다. [SaaS 집필 자료](../public/publication-inventory.md)에도 웹 기여·Tauri·PWA·복원 코드와 최신 검사 근거를 추가해야 한다.

### A11. 링크 오류 후보를 구분하면 실제 경로 오류와 Site 전용 링크가 남는다

로컬 파일이 없는 링크는 110회였다. 91회는 보고 사이트용 `.html` 링크, 16회는 복사해 보존한 타 프로젝트 스킬의 참조, 1회는 과거 README 원문 사본의 상대 경로였다. 이들을 제품 문서 오류 108건으로 세지 않았다.

별도로 [Android 구현 기록](../android-implementation-20261030.md)의 `index.md`는 존재하지 않는다. [소스 범위](../source-coverage.md)의 `Analysis/source-coverage.json`도 현재 작업 트리에 없다. 전자는 문서 목차로 고치고, 후자는 재현 가능한 증거를 연결하거나 원시 자료의 보관 위치를 설명해야 한다.

절 링크 8회도 대상 Markdown에 맞는 앵커가 없다. 쉴카 포탑·럭스루나에 구현 등 Site 생성기가 붙이는 ID를 GitHub Markdown에서 참조한 경우다. 사이트 ID를 유지하면서 GitHub의 실제 제목 앵커 또는 명시적 ID를 연결해야 한다. 전체 후보는 감사 JSON에 있다.

### A12. 검사·TODO·과거 작업 기록의 현재 시점이 섞여 있다

[current-status](../current-status.md)는 최신 결과를 앞에 두고 과거를 보존한다. 이 방식은 작업 이력에는 맞지만, 하위 기록의 ‘병합하지 않았다’·‘배포가 남았다’를 현재 상태로 읽기 쉽다. [TODO](../usability-todo.md)에도 main 병합 후 앱 확인과 Android 아이콘 연결 같은 과거 체크박스가 남아 있다.

최신 상태표에는 현재 남은 일만 두고, 이력은 날짜·커밋으로 연결한다. [공개 검증](../public/validation.md)에는 최신 iPhone 4건·Galaxy 31건·웹 9/11건과 기존 검사의 관계를 적는다. 과거 전체 검사 실패는 보존하되 선택 회귀 검사 성공으로 덮지 않는다.

### A13. CI 성공에 포함되지 않는 새 검사들이 있다

GitHub workflow는 문서, 번역, 자원, C++ 코어와 Apple 빌드를 실행한다. 루트 CMake에는 SaveTransfer 검사 연결이 없고 모듈의 `HM_TRANSFER_TESTS` 기본값은 OFF다. SaveTransfer C++/Wasm·웹 복원·PWA·Tauri Rust 검사는 별도 명령으로 존재한다.

이 검사들이 로컬에서 실행된 증거는 있다. 하지만 GitHub의 기존 초록색 결과만으로 새 플랫폼 전체 회귀를 설명할 수 없다. 관련 변경 경로에 맞는 검사 연결과 실행 환경·소요 시간을 정해야 한다. 이번 감사에서 CI 구성은 변경하지 않았다.

### A14. 복원 코드의 데이터 제한과 보고서 생성 경로를 문서화해야 한다

`SaveTransfer.cpp`는 미션별 스테이지 수 `{4,5,5,5,5,5,6}`, 무기 이름, 등급 범위와 HUD 묶음 수를 검증한다. 현재 데이터에는 맞지만 튜토리얼·새 무기·HUD 묶음을 추가할 때 복원 형식과 검증도 확인해야 한다. 이를 기능 확장 체크에 연결할 문서가 없다.

또한 추적 중인 `tools/build_report_site.py`에는 최근 Tauri 계획·Mac/웹/PWA 비교 페이지의 생성 연결이 없다. 해당 페이지는 로컬 보조 스크립트로 갱신됐다. GitHub에서 받은 자료만으로 보고서를 다시 만들 수 있게 생성 경로를 등록해야 한다. Markdown·사이트 본문·다운로드 사본의 일치 검사도 함께 둔다.

## 수정 순서

1. 정본·작업 지침·기획·실행 정책을 실제 main 기준으로 갱신한다. 승인된 변경 범위와 아직 바꿀 기능을 구별한다.
2. 업무 연결표에 SaveTransfer·PWA와 플랫폼 어댑터·검사를 등록한다. 새 파일 누락과 Markdown 절 링크를 검사한다.
3. 공개 구현 상태 → 구조 → 설치·조작 → 검증·로드맵 → 목차 → SaaS 자료 순서로 보완한다. 영어판도 같은 변경에 포함한다.
4. A08의 전투 중 편집 진입을 별도 코드 수정으로 처리한다. 새 화면 비율에 복원한 HUD, 정지·재개·회전·입력을 검사한다.
5. 새 모듈·플랫폼 검사와 보고서 생성 경로를 저장소에 연결한다. 문서·사이트·다운로드를 대조하고 develop을 거쳐 main에 반영한다.

이 감사에서 작성한 것은 발견 목록·근거·후속 과제다. 위 14개 항목의 수정과 새 릴리스는 아직 진행하지 않았다.
