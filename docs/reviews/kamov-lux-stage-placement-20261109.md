# 카모프·럭스루나에 유로파이터 캠페인 배치

카모프 Ka-52 76대를 전체35개 스테이지에, 럭스루나에 유로파이터21대를 기존14개 편대에 추가했다. 아이폰 정식 앱을 업데이트 설치했고 사용자가 빌드를 확인했다. 채택된 외형·무장·로터와 기존 적의 배치·편대 발동 조건을 유지했다. 기관포 삭제와 미사일2연사는 아래의 후속 TODO이며 이번 설치본에는 적용하지 않았다.

## 배치 범위

일반 캠페인은 7개 미션·35개 스테이지다. `GlobalInfo`의 원작 목록에 미션8 데이터도 있지만 메뉴·저장·다음 미션 진행은 미션7까지다. Stage36~42와 Survival은 이번 배치에서 변경하지 않았다.

쉴카77대·퉁구스카75대의 분포를 참고해 Ka52는 총 76대로 정했다. 각 스테이지에 최소1대씩 배정하고, 나머지는 기존 방공 유닛이 많은 구간에 배분했다. 76대와 미션별 수량은 이 요청을 구현하기 위해 선택한 값이다.

각 미션 예산에서 스테이지마다1대를 먼저 배정했다. 남은 수는 해당 스테이지의 `(방공 수−1)` 비중으로 나누고 소수점이 큰 순서로 배분했다. 같은 소수점은 앞 스테이지부터 채운다. 기존 VTOL 좌표에서 고르게 지점을 고른 뒤 기본 높이를65 올렸다. 지형과 천장·기체 간격을 확인해6개 지점을 옮겼다. 확정 좌표는 실행 MAP에 기록하며 런타임에 새 위치를 계산하지 않는다.

Eurofighter는 보스 조우 편대7회에2대씩, 마지막 구간 편대7회에1대씩 들어간다. 기존 72대에21대를 추가해 총 93대다. 기존 편대 기체의 이름·상대 좌표·보스 조건·진입 속도−2.5·해제 속도−0.5는 보존했다. 새 기체는 기존 마지막 열보다140 뒤의 새 열에 놓고, 2대일 때 세로70 간격을 둔다. 공통 편대 코드가 전체 폭에 맞춰 도착 위치를 계산하므로 편대 전체의 목적지는 기존보다140 왼쪽으로 이동한다. 보스 발동과 마지막 구간 진입 조건은 같다.

## 공통 데이터 경로와 보존

요구 ID는 `HM-KAMOV-LUX-STAGE-PLACEMENT`다. authoring JSON의 `placements`에 Ka52를, `waves`에 Eurofighter를 추가했다. 기존 오프라인 내보내기가 MAP 적 레코드와 HMEX 편대 레코드를 만든다. `GameData`가 읽고 `WorldState::processRegen`과 `GameSession::spawnReinforcements`가 소비한다. 새 C++ 생성·배치 분기는 없다.

기존 고정 추가 배치304개 뒤에 Ka52 76개를 붙여380개가 됐다. 원작 배치1,182개를 포함한 MAP 적 레코드는1,562개다. 기존43개 MAP의 모든 이전 노드와 MCH3개 전체 바이트, 원본 입력을 대조했다. 기체·무기·부품 레코드와 실행 이미지6종×3프로필은 변하지 않았다. 유로파이터는 tileCnt0·rotWpn0과 고정 총구`(-23.5,-9.5)`를 사용한다. 카모프는 원작 type3의 로터2프레임을 유지한다.

## 실행 검사

- 네이티브 코어 28개 검사가 통과했다. 일반·validation 빌드에서 실제 GameSession/MAP 경로로35개 스테이지의 Ka52 76대 생성·중복 방지·재시작을 확인했다. 화면 폭480·696을 각각 검사했다.
- 실제 World 지형을 읽어 각 Ka52 위치의 좌우85 범위에 지면 여유30, 위쪽40의 맵 천장 여유를 확인했다. 기존 VTOL과 수평125 또는 수직65, Ka끼리 수평125 또는 수직60의 간격도 검사했다.
- 기존 14개 편대에서 발동 직전·일시정지 중 생성 억제, 발동 직후93대 구성, 재발동 방지와 재시작을 검사했다. 화면5조건×점프 높이2조건에서 진입 중 간격·지면·천장·동시 도착을 확인했다.
- 기존 로터·무장·포드 없음·고정 총구·실제 탄환 피해·전체 플레이어20무기 피격 검사가 계속 통과했다. 자원 1,771개 SHA-256도 통과했다.

첫 검사에서는 재시작 직후 적이 항상0대라고 가정한 검사 오류를 발견했다. 원래 맵 시작 생성 구간에 있는 적을 포함해 시작 시점의 수가 같아야 한다는 검사로 고쳤다. 이어 천장 여유가 부족한 후보 좌표를 확인해 수정했다. 지형 검사도 `WorldState.openMap`으로 충돌 구간을 실제 초기화하고 꼬리까지 포함하는 폭으로 넓혔다. 실패 로그는 최종 성공 로그와 함께 보존한다.

## 아이폰 정식 앱 설치

iPhone Air / iOS 27.2에 치트 기능이 없는 HeavyMachRestored를 무선 업데이트 설치했다. 최종 서명과 포함 자원116개의 해시를 작업 데이터와 대조했다. 설치 전후·타이틀 실행 후 Documents2개 파일의 내용이 같았다. 타이틀을 확인한 뒤 앱을 종료하고 홈 화면 복귀를 확인했다. 아이폰에서 신규 유닛 전투를 직접 플레이한 결과는 아니다. [설치·보존 근거](../evidence/kamov-lux-stage-placement-20261109/iphone-normal.json).

자원만 바뀐 증분 빌드는 성공 표시 후에도 상위 앱의 서명이 이전 자원을 가리켜 검증에 실패했다. 설치 전에 발견했고, 해당 작업 사본을 Xcode에서 Clean Build Folder 후 다시 빌드해 서명 검사를 통과했다. 실패 로그는 로컬에 보존했다. 증분 빌드 의존성의 근본 수정은 후속 과제로 남겼다.

## 웹 시작 위치와 중간 보스 잠금 조사

웹 캠페인 검사에서 Stage13·Stage25의 Ka52와 Stage13의 Eurofighter가 제한 시간 안에 표시되지 않았다. 생성 수와 편대 발동 구성은 일치했다. 같은 지상 시작 위치를 네이티브 `startValidation`으로 재현해 카메라와 기체 위치를30초 동안 관측했다.

Stage13은 앞선 MBoss05가 살아 있어 전선이X2146, 카메라 중심이X1879.33에 잠겼다. Ka52는Y218에서5초 뒤143.33, 10초 뒤114.34로 내려와 화면 세로 범위−77.8~242.2 안에 있었지만, X약2568로 오른쪽 화면 밖에 있었다. Stage25도 MBoss08 미처치로 전선X1286에 잠겼으며, Ka52는Y약95로 내려왔다. Stage13 Eurofighter 역시 잠금 너머X4602에 시작한 플레이어와 카메라가 분리되어 화면 진입까지20초가 걸렸다.

이 관측에서는 배치 높이보다 선행 보스를 건너뛴 시작 위치가 노출 실패의 원인이었다. 데이터는 변경하지 않았다. 지상에서 앞선 보스를 실제 레이저로 처치하고 키보드로 이동한 보완 검사에서 두 카모프와 Stage13 유로파이터가 화면 안에 나타났다. 무적·탄약 유지 치트를 사용했지만 적 생성·피해·보스 판정은 강제하지 않았다. [시작 조건별 카메라·기체 관측](../evidence/kamov-lux-stage-placement-20261109/visibility-boss-lock.txt).

## 웹 캠페인 검증 결과

일반·치트 웹 빌드를 만들었다. Chrome WebGL에서 35개 스테이지의 카모프76대와 기존14편대의 유로파이터21대 생성·표시를 확인했다. 편대는 발동 전 생성되지 않고 발동 후 기존72대와 함께 총93대 구성으로 생성됐다. 적 강제 생성 호출은0회다. 일반판에는 검증 API가 없고 검증판은 별도 저장을 사용한다.

최종 결과는 한 번의 실행이 모두 통과했다는 뜻이 아니다. run2에서 확인한35맵·14편대의 실제 수량과 정상 표시 결과에, 중간 보스 잠금 때문에 표시를 확인하지 못한3조건의 ground-run2 결과를 합쳤다. 두 실행의 authoring·WASM·RuntimeData 해시가 같음을 확인했다. 중간 run3에 잘못 넣은 방공 수 절반 반올림 검사도 실패 기록으로 남겼다. 이 가정은 승인한 미션별 배분과 달라 제거했다. 제품 데이터는 보완 검사 동안 변하지 않았다.

기체·무장·렌더 소스와 이미지·MCH가 이전 포드 제거판과 같아 이전 웹2종 전투·20무기 검사는 그 범위에 재사용했다. 이번 결과를 휴대폰 실기기 전투나 정상 난이도 전체 클리어로 표현하지 않는다.
