# Mac 두 버전과 웹·PWA 비교

## 설치 우선 시작 화면과 저장 복구

첫 화면에서 **Install game**을 가장 크게 표시한다. **Play in browser**로 설치 없이도 플레이할 수 있다. 처음 페이지를 열 때는 메뉴만 내려받는다. 설치한 PWA를 처음 실행하거나 브라우저 플레이를 선택하면 게임 에셋과 WebAssembly를 받는다. 받은 용량·전체 용량과 검증률을 표시한다. 검사가 끝난 파일은 재시도 때 다시 받지 않는다.

Safari에서는 설치 버튼으로 공유 → 홈 화면에 추가 → 웹 앱으로 열기 순서를 안내한다. 설치 요청 API가 있는 브라우저에서는 설치 창을 연다. 설치형 앱에서는 설치 버튼을 숨기고 Play를 주 버튼으로 표시한다. 캐시를 지우거나 새 버전으로 업데이트하면 다시 다운로드한다.

![설치를 먼저 안내하는 웹 시작 화면](../assets/mac-web-pwa-20261101/launcher-install-first.png)

원작 `Main_BG`, `Main_Title`, `Common_Btn_OK`를 시작 화면에 재사용했다. 버튼 테두리는 원본에서 가져와 늘어나도록 나눴고 새 글자는 HTML로 표시한다. `Distribution/Web/launcher/`를 웹과 Tauri의 빌드 도구가 함께 사용한다. 게임 안의 메뉴와 자원 원본은 바꾸지 않았다.

Tauri에는 Export save·Import save·Restore last backup을 추가했다. macOS 파일 선택 창에서 백업을 내보내고 가져온다. 복구할 때 기존 진행과 백업을 `recovery/`에 보관한다. 복구 도중 앱이 종료되면 다음 시작에서 같은 파일로 복구를 이어간다. 게임 화면에서는 가져오기 명령을 사용할 수 없다.

확인한 결과:

- 설치 전 첫 방문에서 게임 파일 요청 0건. 설치 버튼 우선 노출과 iPad 설치 안내, 390×844·844×390·1024×768·1200×800 배치 검사 통과.
- 다운로드 실패 후 재시도, 검증된 파일 재사용, 실제 용량 표시, 재접속 때 게임 재다운로드 없음, 오프라인 시작까지 9단계 통과.
- Chrome 설치형 PWA에서 첫 실행 다운로드, 이동·점프·사격·정지, 저장 내보내기·가져오기, 오프라인 재실행과 저장 바이트 복원 통과.
- Tauri 저장 관련 Rust 11개·JavaScript 15개 검사 통과. 손상 파일 보존, 복구 중단, 저장소 용량 오류를 포함한다.
- 운영체제 저장 오류 검사도 통과했다. 쓰기 권한 거부와 16 MiB 임시 디스크의 공간 부족에서 이전 백업이 남았다. 공간을 비운 뒤 쓰기도 성공했다. 실제 백업 코드를 실행하는 별도 프로세스를 강제 종료해도 완성된 백업을 읽었고 다음 저장이 성공했다.
- 최종 Release 앱을 메뉴에서 강제 종료한 뒤 다시 실행했다. 시작 화면과 게임이 열렸으며 기존 백업의 해시는 같았다.
- 실제 Tauri Mac 앱에서 파일 내보내기·가져오기·복구 완료. 복구 전 진행과 기존 백업 2개를 보존했고, 복구 후 데이터는 내보낸 파일과 일치했다. 복구 후 게임 실행도 확인했다.

## iPhone·iPad 사용자 플레이와 권한 조사

사용자는 iPad Safari에서 키보드 이동·Space 점프·트랙패드 사격, 비행기 모드 전환과 오프라인 프로필 재진입을 확인했다. iPad Air 설치형 PWA에서는 틸트와 자동조준 사격을 확인했다. iPhone 설치형 PWA는 미션 1-4까지 정상 플레이하고 클리어했다.

동작 허용 팝업은 iPad Air PWA를 껐다 켤 때마다 나타난다는 제보다. 원본 `Web/shell.html`은 새 페이지에서 동작 권한 상태를 초기화하고 첫 입력 때 요청한다. WebKit 공개 구현도 권한을 출처별 메모리 맵에서 조회하고, 값이 없으면 요청 대상으로 돌린다. 따라서 재실행 팝업은 이 권한 수명과 일치하는 현상으로 보인다. 해당 iPadOS의 프로세스 종료·권한 상태를 직접 측정한 결과는 아직 없다. 게임 코드를 우회하거나 로컬 값만으로 권한을 얻었다고 처리하지 않는다. [WebKit 권한 구현](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/WebsiteData/WebDeviceOrientationAndMotionAccessController.cpp).

YouTube 음악과 게임 효과음이 AirPods에서 함께 들린다는 사용자 결과는 오류로 분류하지 않는다. Audio Session 초안은 다른 소리와 함께 재생하는 ambient 유형을 정의한다. 현재 게임의 실제 오디오 세션 유형과 기기별 동작은 별도 검사한다. [Audio Session 유형](https://www.w3.org/TR/audio-session/#audio-session-types).

방향키로 움직이는 `0` 모양은 Chrome 터치 환경에서도 재현됐다. 웹 게임이 수동 조준 위치에 그리는 노란 8×8 사각 테두리다. 방향키 오른쪽·왼쪽 입력에 따라 조준 좌표와 표시가 함께 움직였다. 상단 직선은 같은 검사 화면에서 재현되지 않았다. iPad Safari에서 추가 확인이 필요하다.

![방향키로 이동하는 노란 사각 조준 표시](../assets/mac-web-pwa-20261101/keyboard-aim.png)

Chrome 터치 에뮬레이션에서 미션 진입, 방향키 조준, 세로 회전 때 게임 정지, 가로 복귀, 정지 메뉴의 HUD 편집 진입, 터치 드래그·저장, 새로고침 뒤 같은 HUD 파일 복원을 확인했다. 실제 iPad 검사와는 구분해 기록했다.



2026-11-01. `feat/tauri-mac`에서 기존 네이티브 Mac Release, Tauri Mac Release, Chrome 웹·설치형 PWA 실행을 비교했다. 웹·PWA는 [GitHub Pages](https://gelb2.github.io/HeavyMach/)에 배포했다. 개발 소스는 develop·main에 아직 병합하지 않았다.

## 실행 구조와 저장

| 항목 | 기존 Mac | Tauri Mac | 브라우저·PWA |
|---|---|---|---|
| 게임 계산 | 네이티브 C++ 공용 코어 | 같은 코어의 WebAssembly 빌드 | Tauri와 같은 웹 빌드 |
| 화면 | AppKit·OpenGL | WKWebView·WebGL2 | 브라우저·WebGL2 |
| 소리 | OpenAL Soft | 웹판의 Web Audio 경로 | 웹판의 Web Audio 경로 |
| 진행 저장 | 기존 네이티브 파일 | IndexedDB와 별도 OS 파일 백업 | IndexedDB. 실행 화면에서 파일 내보내기·가져오기 |
| 실행에 필요한 파일 | 앱에 포함 | 앱에 포함 | 최초 다운로드 뒤 오프라인 캐시에 포함 |
| 업데이트 | 앱 교체 | 앱 교체 | 새 파일을 모두 검증한 뒤 기존 창이 닫히면 적용 |

세 실행부는 탄도·공격력·적 이동·스폰·자동조준의 같은 코어를 사용한다. 네이티브와 웹의 메뉴·입력·렌더링 연결부는 다르다. 실제 슬롯 메뉴에서도 삭제 버튼은 네이티브가 오른쪽, 웹이 왼쪽이었다. 해당 기존 구현은 변경하지 않았다.

Tauri·브라우저·네이티브 앱은 서로 다른 저장소를 쓴다. Tauri의 OS 백업은 웹뷰 저장소를 지운 뒤에도 복구에 사용할 수 있다. 브라우저에서는 사이트 데이터를 지우기 전에 Export save로 파일을 남긴다. 설치된 PWA와 브라우저의 저장 공유는 해당 브라우저의 프로필 정책을 따른다.

## 프레임 측정

Mac mini의 Apple M4 Pro에서 측정했다. 게임 앱과 성능 검사 브라우저를 순서대로 실행했다. 네이티브는 기존 XCTest가 실제 게임 타이머와 화면 출력을 사용하며, Tauri·Chrome은 화면 갱신 콜백과 게임 시각 증가량을 읽었다.

| 실행 | 장면·화면 크기 | 평균 갱신 간격 | 95백분위 / 최대 | 게임 갱신 |
|---|---|---:|---:|---:|
| 네이티브 Mac | 첫 미션 사격, 1200×800 | 16.665 ms | 16.911 / 18.442 ms | 약 60회/초 |
| 네이티브 Mac | 첫 미션 사격, 1920×1080 | 16.667 ms | 17.222 / 19.131 ms | 약 60회/초 |
| Tauri Mac | 첫 미션 연속 사격, 1200×768 | 16.668 ms | 18 / 18 ms | 60.01회/초 |
| Chrome 웹 | 첫 미션 시작 위치, 1200×800 | 16.667 ms | 17.6 / 17.8 ms | 60.04회/초 |
| Chrome 설치형 PWA | 첫 미션 연속 사격, 1200×800 | 16.669 ms | 18.3 / 18.8 ms | 59.98회/초 |

네이티브는 장면마다 준비 30회 뒤 180회를, Tauri와 Chrome은 각각 15초를 측정했다. 네이티브의 두 해상도·세 장면 검사에서 저장 함수 호출은 모두 0회였다. 프레임 처리 비용의 95백분위도 16.67 ms 안에 들어왔다. 장면 종료 뒤 화면·미디어·렌더러·오디오 객체의 해제를 확인했다.

Tauri의 첫 타이틀 측정에는 최대 101 ms, 슬롯 메뉴에는 최대 46 ms 간격이 각각 있었다. 최종 빌드의 재측정에서는 타이틀 평균 16.724 ms·95백분위 18 ms·최대 43 ms, 슬롯 메뉴 평균 16.742 ms·95백분위 18 ms·최대 65 ms였다. 메뉴에서 간헐적으로 긴 간격이 발생하는 현상은 남아 있다. 첫 미션 사격 구간에서는 최대 18 ms였다. Chrome GPU 검사에는 `ANGLE Metal Renderer: Apple M4 Pro`가 기록됐다.

이 표는 짧은 실행 결과다. 장면의 적 수·입력 시간·창 높이가 완전히 같지는 않다. 전체 프로세스 메모리·30분 플레이·음향 청취 비교는 남아 있다.

## 확인한 게임 동작

- 네이티브 실제 창: 슬롯 선택, 첫 미션, 이동·점프·사격·일시정지.
- 네이티브 기존 검사: 키보드 이동·조준·점프·사격, 모든 무기 선택과 발사, 두 화면 크기의 세 장면 프레임 검사.
- Tauri 실제 창: 기존 슬롯 재사용, 첫 미션, 연속 사격, 이동·점프·일시정지, 정상 종료. 이전 검사에서는 웹뷰 저장소를 별도 보관한 뒤 OS 백업으로 같은 슬롯을 복구했다.
- 공개 웹 주소: 첫 미션, 이동·점프·사격·일시정지, 동시 창 차단, 저장 내보내기·가져오기, 손상 파일 거부, 오프라인 재실행과 진행 복구.
- 설치형 PWA: Chrome 검사 인터페이스로 설치하고 독립 창을 열었다. 이동·점프·사격·정지와 저장 파일 검사를 통과했다. 네트워크를 끄고 재실행한 뒤 저장 3,624바이트 전체가 같음을 확인했고, 첫 미션에서 탱크 이동과 게임 시각 진행을 확인했다.
- 웹 기존 회귀 검사: 업그레이드 창의 게임 정지, GPU 컨텍스트 복구, 저장 실패 후 재시도 등 19개와 HUD 편집 11단계 통과.

웹 자동 회귀는 별도 Chrome 프로필에서 실행했다. 기능 검사에 쓴 SwiftShader와 위 표의 실제 M4 Pro GPU 측정은 결과 파일을 나눴다.

## 웹·PWA 실행기에 추가한 것

`Distribution/Web/pwa/`에는 시작 화면·manifest·아이콘·Service Worker·저장 파일 관리만 둔다. 기존 게임은 `game/<내용 해시>/` 아래에 복사한다. 설치 또는 브라우저 플레이를 선택한 뒤 약 75 MB를 내려받고, SHA-256이 일치하면 게임을 연다.

웹 저장은 원래 저장 시점을 유지한다. 새 실행기는 시작 전 가져오기와 내보내기만 처리한다. 가져오기 전에는 기존 데이터 사본을 보관한다. 가져오기 중 브라우저가 종료되면 다음 시작에서 나머지 처리를 마친 뒤 게임을 연다. 동시에 열린 브라우저·PWA가 같은 저장소에 쓰지 않도록 Web Lock을 사용한다.

업데이트 검사는 잘못된 해시를 가진 배포를 주입해 확인했다. 잘못된 버전은 활성화되지 않았고, 이전 버전은 오프라인에서도 열렸다. 정상 업데이트도 열린 창을 즉시 교체하지 않았다. 창을 닫고 다시 열면 새 버전이 적용됐고 설정은 남아 있었다.

설치 검사에서 manifest의 상대 `id`가 계정 최상위 주소로 해석되는 문제를 발견했다. `id`를 생략해 고정된 `start_url`인 `/HeavyMach/`를 식별자로 사용하도록 수정했다.
