# 신규 유닛 제작·등록 절차 수정 — 2026-11-09

신규 유닛 8종을 만들면서 기존 데이터 패키징과 공통 표시 경로를 끝까지 따르지 않은 문제가 있었다. Codex는 현재 그림과 전투 동작을 보존하면서 정의·배치·이미지·파츠 소비 경로를 수정했다. 작업 브랜치는 `fix/new-unit-resource-contract`다. Android·PWA·Tauri 치트 검증과 아이폰 일반판 설치를 완료하고 main에 반영했다.

## 문제와 기존 보고의 오류

기존 유닛은 MCH/MAP 데이터에서 정의와 배치를 읽고 공통 파츠와 이미지 로더를 사용한다. 신규 8종은 파싱 뒤 별도 C++ 함수로 정의를 추가했다. 공중 6종은 동체를 직접 표시했고, 지상 2종은 공통 조립 일부와 기종별 이미지 별칭·런타임 crop·축소를 함께 사용했다. 이동·사격·피격 코드를 재사용한 것은 사실이지만, 이를 제작·등록·표시 전체가 원작 절차와 같다는 설명으로 확대하면 틀리다.

새 유닛을 추가하라는 지시는 기존 유닛의 제작·연결 규칙을 따르라는 요구를 포함했다. Codex는 데이터 등록과 에셋 패키징의 차이를 먼저 밝히지 않았고, 일부 공통 전투 코드를 쓴 사실만으로 구현 경로를 충분히 설명했다고 처리했다. 화면이 동작하고 일부 검사가 통과한 것을 구조와 절차 준수의 근거로 삼은 것이 문제였다. 이 차이를 사용자가 확장자와 인터페이스 단위로 다시 지적해야 했다.

탈락한 해리어 그림을 채택본으로 설명한 과거 보고 오류와 정정 이력도 확인했다. GAA의 초기 8방향 설명은 실제 24프레임과 맞지 않았다. 사용하지 않는 PNG 11개도 배포 패키지에 들어 있었다. [전수 감사](new-unit-assets-audit-20261109.md)와 [경위서](new-unit-implementation-incident-20261109.md)에 당시 파일과 근거를 보존했다.

## 바꾼 구조

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 정의·배치 | 파싱 뒤 기종별 C++ factory 호출 | 별도 생성한 실행용 MCH/MAP를 기존 파서로 읽음 |
| 원작 형식 밖 속성 | C++ 상수·분기 | 형식과 필드를 명시한 `UnitExtensions.hmx` 추가 계약 |
| 에셋 | 실행 중 기종별 별칭·잘라내기·축소 | 오프라인 변환한 실제 PNG 63개를 공통 이미지 로더로 읽음 |
| 공중 동체·분사 | 별도 직접 표시 | 공통 재귀 파츠 표시 |
| 패키징 | 사용하지 않는 제작 PNG까지 포함 | 실행용 그림만 포함하고 제작 원본·역사는 저장소에 보존 |
| 누락 검출 | 일부 누락을 실행까지 넘길 수 있음 | 데이터·이미지 파일 집합과 SHA 검사, 필수 확장 파일 누락 거부 |

원작에는 없던 pitch·레이더·Lux 무장 묶음·증원 정보까지 원작 데이터 형식이었다고 주장하지 않는다. 이 속성은 HMEX 계약으로 분리했다. C++는 공통 파서와 소비 로직을 구현하며, 기종별 공장 함수를 제거했다. 원본 개발 소스를 확보한 상태가 아니므로 원작자의 명명·편집 관례 전체가 같다고도 단정할 수 없다. 이번 수정은 확인한 원작 데이터 구조와 복원 프로젝트의 공통 실행 규칙을 기준으로 한다.

새 이미지의 확장자는 `.png`이고 실제 인코딩은 표준 PNG다. 원작 Apple CgBI 이미지와 인코딩은 다르다. 오프라인 변환에서 플랫폼별 기존 crop·필터·알파 결과를 보존하고, 각 플랫폼의 공통 디코딩 결과와 텍스처 업로드에 넘기는 바이트를 비교했다. 원작 파일을 변환본으로 덮어쓰지 않았다.

원작 이미지 695개, RawData 46개와 제작 원본을 보존했다. 실행 패키지에는 원작 형식의 데이터와 추가 계약, 63개 실행용 이미지가 들어간다. 원작 CgBI로 확장자만 바꾸거나 런타임에 이름별 우회로를 남기는 방식은 쓰지 않았다.

## 확인한 결과

- 공용 코어 26개 검사가 통과했다. 원작 3종과 신규 8종, 44조건·39,644틱의 전후 기록에서 이동·발사·탄환·표시 명령·난수·이벤트·저장 결과가 같았다. [비교 파일](../evidence/new-unit-hotfix-20261109/core-trace-comparison.json).
- 플랫폼별 63개 이미지, 합계 189개의 기존 로더 출력과 새 로더 출력을 비교했다. 실제 Apple CoreGraphics 고품질 필터를 사용하는 native Mac·iOS Simulator의 63개 이미지 픽셀 검사도 통과했다.
- iOS Simulator에서 전투·표시·전체 무기 관련 9개와 이미지 보존 1개 검사가 통과했다. native Mac에서는 전투·표시·이미지 보존 9개가 통과했다.
- Mac Chrome에 설치한 PWA에서 신규 8종의 실제 sprite·탄환·HP 감소, 플레이어 무기 20종의 선택·발사, 검증 저장 flush를 확인했다. 검증 PWA는 전용 프로필에서 실행했다.
- 아이폰 일반 빌드 업데이트 직후 기존 저장 파일 2개의 해시가 같았다. 치트 심볼이 없는 빌드다. 사용자는 미션 2-4·2-5를 직접 플레이했다고 확인했다.

Android 에뮬레이터에서 실행 검사 31개, 35스테이지를 포함한 캠페인 검사 39개, 신규 8종의 실제 표시·실탄 HP 감소 8개를 통과했다. 후진 검사 최초 실패는 가로 방향에 기울어진 에뮬레이터 센서 자세에서 발생했다. 센서를 중립으로 놓고 같은 검사를 다시 통과했으며 게임 입력 코드는 바꾸지 않았다. [Android 증거](../evidence/new-unit-hotfix-20261109/android-emulator.json).

실제 Tauri WKWebView에서도 신규 8종의 표시·실탄 HP 감소와 전체 20무기의 실제 발사가 통과했다. 최초 검사는 비활성 창에서 게임이 정상 일시정지해 실패했다. 창 활성화를 기다리고 실제 활성 창에서 재실행했다. 게임의 정지 규칙을 바꾸지 않았다. 일반 Release 앱도 빌드했다. iPhone·iPad 치트 앱은 무료 개발 서명 설치 한도 때문에 설치되지 않았다. 이후 사용자가 아이폰 일반판 설치와 Android·PWA·Tauri 치트 검증으로 범위를 변경했다. 일반 앱 설치를 실기기 치트 검사로 집계하지 않는다.

쉴카 77대와 퉁구스카 75대의 합계는 152대다. Yak 51·Harrier 51·F-35B 50, 총 152대가 현재 배치다. 7개 미션에는 세 기종이 모두 나오고, 35개 스테이지마다 최소 1대가 나온다. 실제 생성 순회와 중복 생성 방지 검사를 다시 통과했다. 모든 스테이지에 세 기종을 각각 추가한 상태는 아니다. 기존 배치 요구가 완료되어 이번 핫픽스에서 수를 다시 늘리지 않았다.

## 검사 중 발견해 보완한 문제

필수 HMEX가 빠져도 초기 로더가 계속 실행할 수 있어 제품 로더에서 누락을 거부하도록 수정했다. 독립 검토에서는 이미지 누락 검출, 승인된 파일 삭제를 스테이징한 뒤의 보호 검사, 일반 Tauri 패키지에 검증 Web 산출물이 섞일 가능성을 추가로 확인했다. 파일 집합·해시와 실제 HTML·JS·WASM의 일반판 설정·검증 export·저장 경로를 검사하도록 보완했다. 독립 회귀 27개가 통과했으며 최초 실패와 재검사 결과를 보존했다.

## 배포 기록

PR #107로 develop `26964ff9`, PR #108로 main `4bbb3f50`에 병합했다. main PR의 Core·Apple 일반/치트 빌드·문서·번역·브랜치 순서 검사를 통과했다. 제품 파일은 검증 커밋 `3729fd35`와 같다. main의 README·개발자의 변 원문을 보존했으며 트러블슈팅은 기존 본문 뒤에 추가했다.

main 병합 커밋에 `new-unit-hotfix-20261109` 태그를 붙이고 [Android 일반·치트 APK와 Tauri Mac ZIP](https://github.com/gelb2/HeavyMach/releases/tag/new-unit-hotfix-20261109)을 게시했다. 공개 웹·PWA 버전은 `5be015e11fcc5269`, 포함한 게임은 `584cf2b910eda1d2`다. [배포 근거·파일 해시](../evidence/new-unit-hotfix-20261109/release.json).

Tauri 일반 앱은 기존 설치본을 업데이트한 뒤 타이틀·슬롯을 확인하고 종료했다. 기존 Lv19 슬롯과 저장 데이터가 같았다. 서명 전후 Mach-O 실행·데이터 15개 섹션, ZIP 재추출 파일, 실제 설치 앱의 일치를 검사했다. [플랫폼별 상세 결과](../evidence/new-unit-hotfix-20261109/web-tauri-validation.json).

공개 주소의 Mac Chrome 설치 PWA에서도 21개 검사를 통과했다. 실제 입력·사격·저장 왕복·손상 복원 거부·오프라인 재실행과 미션 진행을 확인했다. 최초 실행의 타이틀→메뉴 대기 시간 초과는 보존했다. 게임 시간 기록만 추가한 재검사는 입력·대기·판정 조건을 그대로 유지해 통과했으며 최초 실패 원인은 확정하지 않았다. Android PWA의 사용자 확인과 구분한다. [공개 PWA 검사](../evidence/new-unit-hotfix-20261109/public-pwa.json).
